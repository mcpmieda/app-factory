# Architecture — Patrimônio Escolar

## Origin

Generated by `scripts/create-web-admin.mjs` from App Factory `web-admin` baseline `v0.5`, with recipes `database-drizzle` and `auth-better-auth`. See `.app-factory.json`.

## Runtime

```text
Browser
  ├─ Better Auth client → /api/auth/[...all]
  └─ Server Components / Server Actions
       ├─ requireSession() authorization
       ├─ Zod input validation
       └─ Drizzle → better-sqlite3 local file
```

- Next.js App Router owns routing, rendering and mutations.
- Better Auth email/password is active because identity is a requirement; public signup is disabled.
- Drizzle is active because the app owns inventory data.
- SQLite/better-sqlite3 is only the local validation provider, not a production default.
- Versioned migrations create generic settings, auth tables and assets.
- Seed is idempotent and contains only fictitious records.

## UI decision

shadcn/ui remains the sole visual foundation. ReUI was deliberately not activated: server-side search/filtering plus a modest responsive table/card list covers the concrete requirement without a second component layer or TanStack Table.

## Security and recovery

- every protected read/mutation validates a server session;
- Zod validates mutations and codes are unique at both application and database levels;
- `.env.local` and database files are ignored;
- setup creates a random local auth secret;
- migrations rebuild a fresh local database;
- archive is reversible; this example exposes no permanent delete action.
