# V0.9 — Universal Validation

## Resultado

A App Factory reconheceu quatro pedidos não técnicos como famílias diferentes e entregou a menor fatia completa de cada uma. Nenhum piloto herdou o `web-admin`; os quatro têm stack, risco, gates e continuidade próprios.

## Contrato de classificação e handoff

| Pedido simples | Tipo / escala / risco | Fases e ambiente | Stack/reuse e motivo | Decisões da Factory / decisões humanas | Motion / maior fatia autônoma |
| --- | --- | --- | --- | --- | --- |
| “Quero criar um site institucional moderno para uma escola.” | `website` / S / baixo | produto/revisão: ChatGPT; implementação/browser: Codex | scaffold oficial Astro, saída estática e CSS nativo; conteúdo público não pede runtime cliente | Factory decide SSG, estrutura, SEO e testes; usuário só decide marca, conteúdo real, domínio/publicação | `ambient` no hero, `subtle` em leitura; home + rota editorial + CTA |
| “Quero criar um aplicativo para reservar salas e equipamentos.” | `web-app` / S / médio | produto: ChatGPT; fluxo executável/testes: Codex | scaffold oficial Vite React/TS, Zod e estado local; interação real sem backend fictício | Factory decide framework, schema e estados; usuário precisaria definir regras de disponibilidade, identidade e confirmação real | `ambient` contextual + state/interaction; jornada escolha → horário → validação → sucesso |
| “Quero uma extensão do Chrome que facilite uma tarefa repetitiva em uma página.” | `chrome-extension` / S / médio | objetivo/permissões: ChatGPT; bundle/Chromium/package: Codex | scaffold Vite vanilla/TS, MV3/content script e DOM nativo; sem framework/popup/background | Factory decide mecanismo mínimo e host controlado; usuário precisaria aprovar sites reais, dados acessados e distribuição | UI injetada `subtle`; carregar, destacar dois itens e reverter |
| “Quero automatizar a leitura de uma lista e gerar um relatório sem fazer isso manualmente.” | `automation` / S / médio | regras: ChatGPT; CLI/testes/idempotência: Codex | Python stdlib, CSV/JSON, unittest e Ruff dev-only; nenhuma conta/runtime web | Factory decide adapters, dry-run, atomicidade e logs; usuário precisaria definir regra real, origem/destino, credenciais e ownership | não se aplica; ingestão → validação parcial → regra → preview/escrita determinística |

Isto é evidência do contrato de roteamento, não um classificador rígido. Escala/risco mudam quando o mesmo substantivo recebe requisitos de negócio, dados, usuários ou operação diferentes.

## Pilotos e pesquisa curta

### Website — Escola Horizonte

`examples/website-pilot/` usa Astro 7 com duas rotas pré-renderizadas, metadata/canonical, navegação, CTA `mailto:`, foco/teclado, layout responsivo e CSS motion. A documentação oficial descreve `static` como default adequado a conteúdo que muda com pouca frequência e é igual para visitantes; isso eliminou Next.js, React, auth, banco e estado global. Fonte: [Astro rendering modes](https://docs.astro.build/en/basics/rendering-modes/) e [project structure](https://docs.astro.build/en/basics/project-structure/).

### Web app — Encontro

`examples/web-app-pilot/` usa Vite 8, React 19, TypeScript e Zod. O template React/TS oficial economizou bootstrap de bundler, HMR e TS. Estado permanece local e não é persistido porque o piloto comprova UX, não concorrência de agenda. Fonte: [Vite Getting Started](https://vite.dev/guide/).

O fluxo cobre busca/empty recovery, escolha, data/período, validação, loading, sucesso e reinício. Não há dashboard shell, Data Grid, ReUI, auth, banco ou cache cliente.

### Chrome extension — Focus Lens

`examples/chrome-extension-pilot/` é MV3 real com um content script IIFE. Ele injeta um controle acessível na página local, destaca somente `[data-focus-item]` e desfaz toda alteração. O manifest tem zero permissões nomeadas e apenas `content_scripts.matches: http://127.0.0.1/*`; Chrome trata esse match como acesso ao host, delimitado ao fixture local. Fontes: [Chrome permission declarations](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions), [match patterns](https://developer.chrome.com/docs/extensions/develop/concepts/match-patterns/) e [Playwright extension testing](https://playwright.dev/docs/chrome-extensions).

Playwright abriu o Chromium empacotado em contexto persistente com `--load-extension`, encontrou a UI injetada, ativou/reverteu dois destaques e observou console/page errors. O ZIP reproduzível mantém `manifest.json` na raiz e existe apenas em `artifacts/` ignorado/artefato de CI.

### Automation — roster report

`examples/automation-pilot/` usa Python >=3.11 sem dependência de runtime. O fixture gera 3 registros válidos e 1 erro parcial; nomes/departamentos/IDs são normalizados, a regra de treinamento produz uma prioridade e a saída é ordenada. `--dry-run` imprime sem criar arquivo; escrita usa temp file no mesmo diretório, `fsync` e `os.replace`; duas execuções são byte-idênticas. `CONNECTORS.md` preserva a transformação pura ao evoluir adapters.

## Living UI

Living UI funcionou sem biblioteca visual ou motion library. O website limita ambiente ao hero e atenua leitura; o web-app usa atmosfera contextual, microinteração e feedback de loading/sucesso; a extensão usa apenas feedback curto na UI injetada. Website/web-app têm projetos reduced-motion executáveis. A automação não tem UI: logs claros são o feedback proporcional.

## Continuidade entre agentes

Em 2026-08-21, dois agentes read-only foram iniciados sem histórico da conversa (`fork_turns: none`).

- `website`: recuperou produto, duas rotas, estado V0.9, todos os comandos/gates, próxima ação de revalidar/substituir apenas conteúdo aprovado e restrições anti-admin. Apontou corretamente que logs completos dependem de CI e que publicação/conteúdo real não pertencem ao piloto.
- `automation`: recuperou transformação/regra, estado, comandos, dry-run/idempotência, próxima ação via `CONNECTORS.md` e restrições de segurança. Notou que Python mínimo estava apenas implícito; o handoff foi corrigido para declarar `>=3.11` em `pyproject.toml`, README e estado.

Ambos responderam às cinco perguntas usando somente arquivos do piloto. O alerta temporário de que os diretórios ainda não estavam rastreados deixa de existir no commit/PR desta fase; resultados de execução passam a ser recuperáveis pelos checks do GitHub.

## Verificação local

- website: format, Astro check, build estático de 2 páginas, audit sem high/critical; Playwright 7 passed/2 skips esperados em desktop/mobile/reduced-motion;
- web-app: format, Oxlint, TypeScript, 4 Vitest/Testing Library, build, audit; Playwright 7 passed/2 skips esperados;
- extension: format, TypeScript, 2 Vitest, build, audit, package ZIP e 1 Playwright Chromium persistent-context passed;
- automation: Ruff format/lint, compileall, 4 unittest, dry-run sem escrita e integração de repetição byte-idêntica;
- Factory: validators estruturais e regressões existentes são executados novamente no gate final/CI.

O workflow `Validate Universal Pilots` mantém quatro jobs independentes e o ZIP como artifact. Os workflows existentes permanecem separados e não foram alterados.

## Respostas exigidas

1. **Distinguiu os quatro tipos?** Sim; o contrato acima mostra produto, escala, risco, ambiente e slice diferentes a partir de linguagem comum.
2. **Evitou `web-admin` por reflexo?** Sim; não há Next/shadcn/ReUI/admin shell nos quatro pilotos.
3. **Stacks e motivo?** Astro estático para conteúdo; Vite/React para jornada cliente; Vite vanilla/MV3 para extensão; Python stdlib para arquivo local.
4. **Onde reuse-first economizou?** Scaffolds oficiais Astro/Vite, Zod, Playwright, Chromium empacotado, Archiver e Ruff evitaram infraestrutura própria; DOM/Python stdlib evitaram dependências sem ganho.
5. **Living UI transversal?** Sim, por CSS/DOM e feedback de estado, sem forçar design system; não se aplica à CLI.
6. **Extensão testada de verdade?** Sim, unpacked em Chromium persistent context, ação e reversão observadas, console limpo.
7. **Automação segura/determinística/recuperável?** Sim, preview sem escrita, erro parcial, atomic replace, output estável e documentação de adapters.
8. **Outro agente continuou sem chat?** Sim, website e automation passaram o teste read-only; a única lacuna acionável (Python mínimo) foi corrigida.
9. **Status dos perfis?** Todos `validated`; nenhum ainda tem repetição suficiente para `v1-rc`.
10. **Bloqueador objetivo antes da V1.0?** Nenhum dentro do escopo V0.9, condicionado aos checks do draft PR verdes.
11. **Menor correção se houver?** Se CI revelar divergência Linux, corrigir somente o job/piloto afetado e repetir seus gates; não criar fase intermediária.
12. **Declaração:** `READY FOR V1.0 FINAL AUDIT`.
