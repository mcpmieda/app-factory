# V0.2 — Matriz preliminar de referências

> Estado: triagem inicial. Esta matriz NÃO congela a stack. `ADOTAR` significa candidato forte para integrar como padrão ou mecanismo; ainda exige inspeção de licença, manutenção, API e compatibilidade antes da decisão final.

## Legenda

- **ADOTAR (preliminar)** — candidato forte para padrão/default.
- **ADOTAR (condicional)** — forte, mas somente quando o tipo de projeto precisar.
- **INSPIRAR** — estudar arquitetura/processo; não incorporar automaticamente.
- **DESCARTAR como default** — pode continuar como referência histórica/compatibilidade, mas não deve ser escolha inicial da Factory.

## Primeiras conclusões da triagem

1. **Skills precisam ser tratadas como produto de primeira classe.** Há repositórios oficiais tanto da OpenAI quanto da Anthropic dedicados a Skills; nossa escolha de `skills/*/SKILL.md` está na direção correta.
2. **Não devemos criar um starter universal gigante.** `create-t3-app`, `next-forge` e outros reforçam a utilidade de composição por capacidades/opções.
3. **shadcn + ReUI continuam sendo o melhor eixo preliminar para admin**, mas HeroUI fica como perfil alternativo e Magic UI como acabamento seletivo.
4. **Playwright merece posição central na Definition of Done web**, porque permite validar comportamento real, não só build.
5. **Better Auth + Drizzle + Zod são candidatos fortes**, mas serão auditados antes de virar default.
6. **Segurança deve ser em camadas e proporcional:** proteção nativa primeiro; Gitleaks/Semgrep/OSV entram quando adicionarem cobertura concreta.
7. **Observabilidade, release automation, Storybook, Turborepo e Renovate não devem ser universais.** São módulos condicionais.

## Próxima etapa

Auditar profundamente uma shortlist de aproximadamente 15–20 itens: README, licença, releases/atividade, dependências, arquitetura, testes, CI, issues recentes e compatibilidade entre si. Só depois promover candidatos de `preliminar` para decisão definitiva da V0.3.
