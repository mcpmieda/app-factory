# Project Adoption Gate

Read `core/PROJECT_ADOPTION_GATE.md` first.

## Trigger

Use this Skill before functional/visual implementation when:

- the user explicitly says to use App Factory;
- `.app-factory.json` exists;
- project docs/AGENTS declare App Factory governance;
- the repo came from an App Factory starter;
- durable Factory state/spec artifacts already identify the repo as Factory-governed.

Do not permanently inject governance into an unrelated legacy repository merely because `factory-router` activated for a tiny repair. Explicit/project-level adoption is the boundary.

## Required order

1. Recover the real repository state.
2. Classify scale, risk and system level.
3. Classify API mode.
4. Classify Semantic Verification + semantic depth.
5. Classify Independent Verification mode.
6. Select validated profile when applicable.
7. For UI, select the design system and Professional UI/Motion profiles **before code**.
8. Initialize/update durable adoption metadata.
9. Materialize semantic artifacts required before implementation.
10. Run the read-only `pre-implementation` gate.
11. Only after it passes, implement the functional slice.

## Executable path

When the App Factory repository/runtime is locally available:

```bash
python scripts/project_adoption_gate.py init --project <repo> \
  --mode existing \
  --scale L \
  --risk medium \
  --system-level production-system \
  --profile web-admin \
  --api-mode lightweight \
  --semantic required \
  --semantic-depth domain \
  --independent adversarial \
  --authoritative-data "<source>" \
  --identity "<identity model>" \
  --authorization "<server-side authorization>" \
  --recovery "<recovery model>"

python scripts/project_adoption_gate.py check --project <repo> --phase pre-implementation
```

These flags are technical routing decisions. Infer them; do not ask the user unless a real product/organizational decision is missing.

If the script cannot run, apply the same checklist manually and persist the same `.app-factory.json`, `AGENTS.md` and `PROJECT_STATE.md` contract before implementation.

## UI guard

For `web-admin` UI:

- default foundation: shadcn/ui;
- ReUI: selective advanced complement;
- HeroUI: explicit/transversal override;
- React + custom/native CSS is **not** an implicit design-system choice and requires a documented `ui.deviation` when used as the visual foundation.

For HeroUI primary systems, automatically record:

```text
Motion Profile: ambient
Ambient Surface Profile: ambient-constellation
Constellation Intensity: strong
```

Then follow `ui/AMBIENT_CONSTELLATION_PROFILE.md`.

## Recovery of already-started projects

If code already exists and the gate fails:

- do not pretend the project was compliant earlier;
- do not rewrite working infrastructure by reflex;
- record the real current state and deviations;
- apply missing Factory contracts before the next material slice;
- correct architectural/UI gaps in a safe planned block;
- use Change Hygiene when replacing ad-hoc layers.

## Delivery

Before completion, run:

```bash
python scripts/project_adoption_gate.py check --project <repo> --phase delivery
```

This adds delivery-level checks such as review evidence for medium/high semantic risk and recoverable Independent Verification state above baseline.
